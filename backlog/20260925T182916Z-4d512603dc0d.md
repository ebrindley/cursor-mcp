## Description

Archive or unarchive many agents from one MCP call. Cursor has no bulk endpoint, so the server runs a paced background job.

## Scope / Surfaces Affected

- src/bulk-job.ts (new): pacer, backoff, per-id ledger, job lifecycle.
- src/tools/bulk.ts (new): `cursor_start_bulk_job`, `cursor_get_bulk_job`, `cursor_cancel_bulk_job`.
- src/config.ts: optional policy `bulk` block (writesPerMinute 80, readsPerMinute 240, maxInFlight, max429Retries, backoff).
- src/server.ts registration and shutdown; docs/reference.md, docs/cursor-capabilities.md, README, policy.example.json; tests.
- Measured limits (2026-09-25): get_agent_status 300/min, archive_agent 100/min; headers only on 429.

Out of scope: overlapping jobs, per-call rate overrides, restart durability, CLI entry point, batch delete.

## Acceptance Criteria

- Given 100 allowed ids, when one start call is made, then the job archives all 100 without further calls and status reports 100 archived.
- Given writesPerMinute N, when a job runs, then no 60s window of POST attempts exceeds N (fake clock).
- Given a 429 with Retry-After R, when the job hits it, then it waits at least R and retries; after max429Retries the item is failed.
- Given a usage-exhausted 429, when the job hits it, then the job stops and remaining ids are reported not submitted.
- Given a cancel, when in-flight requests settle, then no new request starts and completed writes are not reverted.
- Given a POST whose response is lost, then the item is reported uncertain, not failed or pending.
- Given a profile without the tools, then they are not registered.

## How to Verify

Focused vitest for engine and tools must pass; `npm run typecheck` and `npm run build` must succeed.
