# Bulk archive/unarchive as a paced background job

## Description

## Description

Archive or unarchive many agents from one MCP call. Cursor has no bulk endpoint, so the server runs a paced background job.

## Scope

- `cursor_start_bulk_job` (archive|unarchive, explicit ids), `cursor_get_bulk_job`, `cursor_cancel_bulk_job`.
- One active job per server; bounded retained results; job lifetime independent of the start request.
- Policy `bulk` settings: writesPerMinute (80), readsPerMinute (240), maxInFlight, max429Retries, backoff; applied to every HTTP attempt.
- Fresh scope resolve with identity check before every POST attempt, including retries.
- Honour Retry-After; capped exponential backoff with jitter otherwise; usage exhaustion stops the job.
- Per-id states: pending, inFlight, retrying, archived/unarchived, denied, unresolved, failed, uncertain, cancelled.
- Measured limits (2026-09-25): get_agent_status 300/min, archive_agent 100/min; headers only on 429.

Out of scope: overlapping jobs, per-call rate overrides, restart durability, CLI entry point, batch delete.

## Acceptance Criteria

- One start call processes up to the id cap without further calls; status reports per-id outcomes and counts.
- Request rate never exceeds configured per-endpoint budgets in tests (fake clock).
- 429 with Retry-After waits and retries; exhausted retries mark the item failed; usage exhaustion stops the job.
- Cancel stops admissions, lets in-flight requests settle, never reverts completed writes.
- Tools register only under a profile that allows them.

## How to Verify

Focused vitest for the engine and tools; typecheck; build.
