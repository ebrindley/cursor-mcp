# Interpret asctime Retry-After dates in UTC

## Description

## Scope / Surfaces Affected
Accepted B4 in the existing Retry-After parser and client tests. RFC 9110 section 5.6.7 explicitly defines asctime HTTP dates as UTC: https://www.rfc-editor.org/rfc/rfc9110.html#section-5.6.7.

## Acceptance Criteria
The same asctime Retry-After header yields the same delay under UTC and America/New_York. Existing decimal delays, GMT dates, backoff ceilings and retry counts are preserved. No new date rejection or dependency.

## How to Verify
Reproduce the timezone-dependent delay with a fixed wall clock and restored per-test TZ, rerun the exact client file, run changed-test selection once and typecheck. Do not change the user environment.
