## Description

Whether this server should offer a file transfer tool for VM terminals, or leave staging to the caller.

## Scope / Surfaces Affected
- Decision only; no source change unless the decision is to build.
- If built: a new tool registration in `src/tools/terminal.ts`, a transfer module beside `src/terminal.ts`, and a section in `docs/terminal.md`.

## Context
Each execute command and each session input is capped at 16,384 UTF-8 bytes, so a caller moving a larger file splits it, reassembles it on the VM, and verifies it. The terminal gateway carries PTY operations only, so a server-side transfer would run over the same channel as caller-side chunking.

Two caller-side routes exist:
- Materialize the file from the VM's repository checkout, for example `git archive` of a ref, and reference it by path.
- Have the agent write the file in its own workspace.

Beyond chunking, a server-side tool would need machine binding, because a PTY gateway can move between machines; retry-safe chunk identity, so that an uncertain resend cannot duplicate or truncate; and destination-side whole-file digest verification.

## Acceptance Criteria
- A recorded decision either to build the tool or to keep the caller-side routes as the answer.
- If built: a documented per-call size, machine binding, retry-safe chunk identity, and destination-side digest verification, with tests covering a resend under uncertain delivery.

## How to Verify
- Not applicable until the decision is to build.

## Reconsider When
- A payload cannot be committed anywhere, cannot be generated on the VM, and does not fit an agent prompt.
- Caller-side chunking proves repeatedly unreliable in practice.
