# Say what an acknowledged wake that did not restore the terminal means

## Description

`cursor_terminal_wake` returns `wakeOutcome: "signaled"` with `readiness: "deadline"` when Cursor acknowledges the wake but the terminal gateway stays unavailable. Live tests on 2026-11-14 showed this is what happens for a suspended VM: the VM clock stayed stopped through two acknowledged wakes and resumed two seconds after an agent run was created. The result gives the caller no diagnosis and no next step, and the plugin-facing docs do not say what a wake can and cannot recover.

## Scope / Surfaces Affected

- `src/terminal.ts` wake result for the acknowledged-but-not-ready case.
- `src/tools/terminal.ts` tool description for `cursor_terminal_wake`.
- `docs/terminal.md` and `docs/cursor-capabilities.md` wake sections.
- Unit tests for the wake result.

## Acceptance Criteria

- When the wake was acknowledged and the gateway did not become ready before the wait ended, the result states the observation (acknowledged, still unavailable after the wait), offers a hedged diagnosis (the VM is probably suspended) and names the next step (an agent run resumes it; `cursor_keep_awake` sends a minimal one).
- No change to what the wake sends, no retry, no agent run from the wake tool.
- Other wake outcomes are unchanged.
- Docs say a wake recovers a dropped gateway connection on a running VM and does not resume a suspended VM.

## How to Verify

- `npm run typecheck` and the focused wake tests in `tests/terminal.test.ts` pass.
