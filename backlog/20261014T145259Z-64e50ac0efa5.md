# Accept image inputs on agent create and follow-up

## Description

## Scope / Surfaces Affected
- `cursor_create_agent` and `cursor_create_run` input schemas and request bodies (src/tools/agents.ts), tests, docs/reference.md.
- Adds optional `images` mapped to `prompt.images` (OpenAPI CreateAgentRequest / CreateRunRequest).
- Out of scope: bulk create, delegated-run, environment-lifecycle launch paths.

## Acceptance Criteria
- Each image is either `{ url }` (https only) or `{ data, mimeType }` (base64); max 5 per call.
- Inline data limited so one MCP message stays under the 10 MiB stdio buffer: decoded total <= 6 MiB per call; per-image and total limits enforced before any network I/O.
- Image data never appears in tool text, structured output, errors, or logs; output reports count only.
- Omitted `images` leaves request bodies byte-identical to today.

## How to Verify
- Focused vitest on tests/agents.test.ts: body mapping, url/data validation, limit rejection before fetch, redaction.
- Live: create agent with one image URL and follow up with one inline PNG; run reads the image content.
