# Read secret-name inventory through Workspace Controls

## Description

## Scope / Surfaces Affected
- Workspace Controls `secrets` row (src/workspace-controls.ts, src/tools/account.ts), tests, docs/reference.md, docs/cursor-capabilities.md workspace-controls table row for secrets only.

## Acceptance Criteria
- Secret-name inventory read through the published API: GET /v1/environments/{id}/secrets for an environment the profile can access, GET /v1/team/secrets for team scope; GET /v1/secrets only with explicit opt-in because admin keys can see other members' personal metadata.
- Paginate until nextCursor is null, including empty pages, with a bounded page/time budget.
- Output: name, type, owner/scope, repos, version metadata; never a value; redaction applies to any value-like field.
- 403 feature_unavailable/key_not_supported/repository_access/team_membership_required/team_admin_required and 404 environment_not_found map to explicit capability results.
- Writes remain unsupported by this MCP; row text updated to say the API publishes writes but this server does not perform them.

## How to Verify
- Focused vitest on workspace-controls and account tool tests.
- Live: inspect secrets for one environment and team scope; compare names with dashboard; no values present.
