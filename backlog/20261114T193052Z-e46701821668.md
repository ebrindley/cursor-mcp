# Add cursor_keep_awake: one minimal agent run that keeps or brings a VM up

## Description

A Cursor Cloud Agent VM is suspended some minutes after its last agent run; Cursor documents that follow-up prompts refresh that timer and offers no other way to keep a VM up or to resume a suspended one. Callers currently hand-write a minimal `cursor_create_run`. Add one plain tool that sends a minimal agent run and reports whether the terminal is ready afterwards, for use as a keep-awake signal and as the recovery step after a wake that did not restore the terminal.

## Scope / Surfaces Affected

- New tool `cursor_keep_awake` (registration, schema, policy gating as for `cursor_create_run`).
- Docs: `docs/reference.md`, `docs/terminal.md`, README tool list if it enumerates tools.
- Unit tests with fake transports.
- Package version bump.

## Acceptance Criteria

- `cursor_keep_awake` takes an agent id and a bounded wait; it creates exactly one run with a fixed minimal prompt, waits for it to finish within the bound, then reports the run id and status, the terminal status, and the run's token usage including cached tokens when the API returns it.
- It never retries the run creation. An agent that already has an active run is reported as already active without creating a run. An archived agent is reported as such.
- It is subject to the same policy and model pin as `cursor_create_run`.
- The tool, its description and the docs contain no intervals, cache lifetimes or suspension timings; scheduling is the caller's.

## How to Verify

- `npm run typecheck`, the new focused tests, and the tool-registration tests pass.
