# Release settled terminal results instead of refusing new commands

## Description

## Summary
A command session retains at most 32 results and never evicts one, so the 33rd execute returns session_capacity. Reset is the only release and it refuses while any command is active or any cleanup is unresolved, including a machine_changed cleanup that can never resolve further. A client that polls with many short commands locks its own command channel for the rest of the server process.

## Scope / Surfaces Affected
- src/terminal.ts: release settled, fully read results oldest first when the session is full, keeping a small tombstone per released command ID so a resent ID is reported and never executed again; machine_changed counts as resolved; reset releases resolved records and carries unresolved and active ones into the new session instead of refusing
- src/tools/terminal.ts tool descriptions and docs/terminal.md
- tests/terminal.test.ts

## Acceptance Criteria
- If 32 results are settled and fully read, then a 33rd execute runs and the oldest result is released.
- If a released command ID is sent again with the same source and timeout, then it returns result_released and is not executed; with different source it returns command_id_conflict.
- If no retained result is releasable, then execute still returns session_capacity.
- Reset succeeds with an active command or a machine_changed cleanup; unresolved records stay readable under the new session ID.

## How to Verify
- npm run typecheck, npm test, npm run build, npm run check:bin.
